# Центр сервиса «Студент» · МГИМО

Работающий учебный прототип сервисного центра и личного кабинета: расписание, успеваемость, пять видов справок, статусы, документы, уведомления, профиль, избранное, подбор услуги, архив документов, единое обращение с маршрутизацией и обработка обращений сотрудником. Дизайн и сценарии основаны на исследовании студенческого сервиса ВШЭ и проблем разрозненных систем МГИМО. Только вымышленные данные.

Тестовые аккаунты и сценарии: [docs/JURY.md](docs/JURY.md). Архитектура и границы прототипа: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

Продуктовый бизнес-кейс, user stories, приоритеты и роадмап: [docs/product/PLAN.md](docs/product/PLAN.md). Выполнение текущей итерации и её приёмка: [docs/product/EXECUTION.md](docs/product/EXECUTION.md).

## Локальный запуск

Нужны Node >=22.13 и npm. Зависимости зафиксированы в package-lock.json.

```powershell
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_freezing_swarm.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_damp_network.sql
npm run dev
```

Открыть адрес из терминала, обычно http://127.0.0.1:5173. Миграцию выполнить один раз для пустой локальной базы. Данные сохраняются в `.wrangler/state`, эта папка исключена из Git. Учебные аккаунты добавляются идемпотентно при первом запросе API. Для проверки собранного Worker вместо dev: `npm start`.

Проверки:

```powershell
npx tsc --noEmit
node scripts/verify-portal.mjs
```

Сценарный API-тест запускается против работающего локального сервера, создаёт учебные заявки и сохраняет отчёт в `outputs/`. Для другого адреса задайте `PORTAL_TEST_URL`. Проверка включает доступ к чужой заявке и файлу, роли, CSRF, все пять услуг, идемпотентность, уточнение и завершение сотрудником, прочитанность уведомлений и выход.

Для изолированной локальной БД можно задать `PORTAL_QA_STATE` перед `npm run dev`; сначала примените обе миграции Wrangler с таким же `--persist-to`. Переменная действует только в dev-режиме. Приёмка также проверяет личные уведомления о заявках, самостоятельную отмену до начала обработки и конкурентное изменение статуса. Для повтора большого прогона используйте отдельную тестовую БД, чтобы не упереться в дневной лимит демонстрационного аккаунта.

## Публикация и перенос

Проект подготовлен для Sites / Cloudflare Worker с D1 binding `DB`, объявленным в `.openai/hosting.json`. Миграции схемы лежат в `drizzle/`. Для переноса на самостоятельный Cloudflare deployment нужны собственный Worker, D1, перенос конфигурации и применение миграций. Не публикуйте локальную базу и сессии. ИИ-сервисов и их ключей приложение не использует.

## Лицензии и материалы
