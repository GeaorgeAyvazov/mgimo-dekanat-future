# Центр сервиса «Студент» · МГИМО

Учебный кабинет для московского МГИМО объединяет расписание, оценки по шкале из 100 с ECTS, справки, первичные заявки и семь действующих маршрутов университета. Сервисный центр сохраняет комплект PDF и SIG, ведёт историю бумажной выдачи, принимает сообщения о проблемах и формирует отчёт по работе с заявками. В учебных записях используются вымышленные данные.

Тестовые аккаунты и сценарии: [docs/JURY.md](docs/JURY.md). Архитектура и границы прототипа: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

Репозиторий: https://github.com/GeaorgeAyvazov/mgimo-dekanat-future

Продуктовый бизнес-кейс, user stories, приоритеты и роадмап: [docs/product/PLAN.md](docs/product/PLAN.md). Выполнение текущей итерации и её приёмка: [docs/product/EXECUTION.md](docs/product/EXECUTION.md).

## Локальный запуск

Нужны Node >=22.13 и npm. Зависимости зафиксированы в package-lock.json.

```powershell
npm ci
npm run build
Get-ChildItem drizzle -Filter '*.sql' | Sort-Object Name | ForEach-Object {
  node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file $_.FullName
  if ($LASTEXITCODE -ne 0) { throw "Migration failed: $($_.Name)" }
}
npm run dev
```

Откройте адрес из терминала, обычно http://127.0.0.1:5173. Команды выше рассчитаны на пустую базу. Для существующей базы примените только новые миграции по порядку. Данные сохраняются в `.wrangler/state`, эта папка исключена из Git. Учебные аккаунты добавляются при первом запросе API. Собранный Worker можно запустить командой `npm start`.

Проверки:

```powershell
npx tsc --noEmit
node scripts/verify-portal.mjs
node scripts/verify-office-report.mjs
```

Сценарный API-тест запускается против работающего локального сервера, создаёт учебные заявки и сохраняет отчёт в `outputs/`. Для другого адреса задайте `PORTAL_TEST_URL`. Проверка включает доступ к чужой заявке и файлу, роли, CSRF, выпуск справок, обращения по экзаменам и данным, идемпотентность, уточнение и завершение сотрудником, прочитанность уведомлений и выход.

Для изолированной локальной БД задайте `PORTAL_QA_STATE` перед `npm run dev` и примените все миграции Wrangler с таким же `--persist-to`. Переменная действует в dev-режиме. Используйте отдельную тестовую базу для повторных полных прогонов, поскольку у демо-аккаунтов есть дневной лимит заявок.

Сервер выпускает отсоединённую подпись CMS RSA/SHA-256 с самоподписанным учебным сертификатом. Для новых справок PDF, SIG и хеши сохраняются в транзакции готовности. Для старых готовых заявок комплект формируется при первом обращении к файлу. Сверка в браузере сравнивает хеши обоих файлов с данными заявки. Университетское подписание и доверенная проверка сертификата требуют отдельного подключения.

## Публикация и перенос

Проект подготовлен для Sites / Cloudflare Worker с D1 binding `DB`, объявленным в `.openai/hosting.json`. Миграции схемы лежат в `drizzle/`. Для переноса на самостоятельный сервер используйте инструкции `deploy/UBUNTU.md`. Не публикуйте локальную базу и сессии. ИИ-сервисов и их ключей приложение не использует.
