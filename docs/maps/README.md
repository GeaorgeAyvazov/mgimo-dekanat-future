# Встроенная карта московского кампуса

Карта открывается внутри кабинета из меню «Карта» и из расписания по номеру аудитории. На выбранном этаже все доступные планы расположены на одном полотне. Можно перемещаться между корпусами, нажать на корпус для приближения или найти помещение по номеру и названию.

## Источники и состав

- [Официальная карта МГИМО](https://mgimo.ru/territory/), публичная часть, снимок 06.11.2026. Каждый из 31 адреса этажей указан в [SOURCES.md](SOURCES.md).
- `public/maps/indoor.json`: 31 план, 1293 помещения и объекта. Это не перечень только учебных аудиторий: в нём также лестницы, переходы, кабинеты, кафе и другие обозначенные места.
- `public/maps/floors/`: локальные векторы этажей; `mgimo-moscow.svg`: общая схема кампуса. Рабочий сценарий не зависит от доступности сайта МГИМО, внешних iframe, аналитики и его скриптов.
- [validation-report.json](validation-report.json) фиксирует восемь пройденных проверок и хеши файлов. 13 исходных объектов без ненулевой доступной геометрии исключены; координаты не придумывались. Несколько исходных обозначений выходят за границы собственного плана и не предлагаются поиском.

В интерфейсе сохранена ссылка на источник. Использование - некоммерческий учебный прототип. Карта не означает согласования проекта с университетом. Актуальность расположения комнат на местности отдельно не проверялась.

## Как подготовлены данные

1. Обычным Browser Use открыт публичный сайт, в его форме прочитаны действительные корпуса и этажи. Защита сайта не обходилась. Первые HTTP-запросы возвращали защитный HTML, который не приняли за данные карты.
2. Из успешно отрисованных страниц прочитаны DOM-вектор `#main_map` и текст встроенных литералов `Rooms`/`RoomsRewrite`. Большие SVG сохранены порциями с проверкой неизменности длины: один ранний снимок G0 оказался обрезан, его получили заново.
3. Скрипты сайта не исполнялись в сборщике: TypeScript AST извлёк только литеральные объекты. Исправления `RoomsRewrite` применены поверх базовых полей.
4. Сохранены видимые геометрические границы элементов SVG. Исходные CSS-заливки и номера материализованы в векторе, чтобы он отображался без стилей чужого сайта. У пяти декоративных повторных элементов A2 удалены повторные ID, фигуры сохранены.
5. XML-санитизация удаляет активное содержимое и внешние ресурсы. В JSON перенесены только ID, название, тип и границы. Описания с контактами, телефоны, email, произвольный HTML и исполняемый код в приложение не попали.

Готовые данные входят в исходный код. Для обновления карт сохранены `build-map-assets.mjs`, `extract-floor-metadata.mjs` и индекс этажей. Генератор принимает папку со снимками `<этаж>.svg`, `.scripts.html`, `.geometry.json`, `.styles.json` и `floor-index.json`:

```text
node docs/maps/build-map-assets.mjs --input <папка-снимков> --strict --python <путь-к-Python>
```

Сырые HTML-страницы и тексты сайта в конкурсный архив не включены. В архиве есть полученные инертные векторы, минимальный JSON, код преобразования, источники и протокол проверки.

## Привязка и мобильный сценарий

В деморасписании сохранены явные `roomId` вида `b2:2009`: ID этажа и ID помещения. Номер для показа берётся из проверенной пары, а не преобразуется в предполагаемый адрес. Вымышленные занятия используют настоящие номера из публичной схемы; студенты, оценки и заявки остаются вымышленными.

Карта поддерживает кнопки масштаба, колёсико мыши, перетаскивание и обработчики жестов двумя указателями. В браузере проверены мышь, клавиатура и интерфейс при 360 px. Проверка двухпальцевого жеста на физическом телефоне ещё не проводилась. После закрытия восстанавливаются прокрутка и фокус на нажатой аудитории.

Планы состыкованы по стрелкам на исходных SVG. Форма каждого плана сохранена, а зазоры у стыков заполнены коридорами. Масштаб и длина перемычек схематичны. В одном уровне карты могут быть этажи с разными номерами: Г1 соединён с «Трёшкой» на втором этаже, Г2 — с Н3, Г3 — с Н4, Г4 — с Н5. Стык А2–Б1 совмещён по ответной стрелке в Б1. Стрелка А1 сохраняет ссылку на Б1.

Подземный переход из цоколя Г в библиотеку на исходном плане помечен закрытым. Библиотека показана отдельным планом, вход с кампуса доступен в поиске. На первом этаже стрелкой вверх обозначен подъём, а для отмеченных в источнике спусков и специальных проходов используется нейтральная метка.

Пары переходов хранятся в `lib/campus-passages.json`. У Г4–В4 нижняя стрелка из В4 указывает на одноимённую метку Г4, а обратная ссылка исходного сайта ведёт на В2. На карте стык показан по положению стрелок В4 и Г4. При сборке скрываются повторные подписи стыков и стрелки закрытого перехода. Геометрия помещений, номера аудиторий и метаданные сохраняются.


## Календарь помещения

«Расписание аудитории» показывает время, предмет и группу через авторизованный `GET /api/portal/room-calendar`. Поиск через `GET /api/portal/room-availability` использует тот же календарь для всех учебных аудиторий. Он проверяет весь интервал по московскому времени, включая частичные пересечения с занятиями любой группы. Соседние интервалы могут соприкасаться по границе. Обе функции работают на вымышленных занятиях нескольких факультетов.
