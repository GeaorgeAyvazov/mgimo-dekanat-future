## Решения текущей итерации

- Уведомления строятся из событий заявок: они отражают факт, уже сохранённый в транзакции, и не зависят от второй необязательной записи «отправить уведомление». В ленте показываются последние 100 значимых событий и объявления.
- Кабинет проверяет изменения в активной вкладке раз в 30 секунд, при возвращении в неё и при открытии уведомлений. Это обновление в кабинете; email, SMS и push не подключаются.
- Отмена студентом разрешена только до начала обработки. Автоматически готовый PDF и уже обрабатываемая заявка самостоятельно не отменяются.
- Ошибка конкурентного изменения остаётся ошибкой с понятным сообщением; текст уточнения не удаляется из поля при отказе сервера.
- Бумажная выдача, календарь филиала, назначение исполнителя и черновики остаются следующими историями. Их выполнение не заявляется заранее.

## Ограничения приёмки

Вымышленные аккаунты и учебные документы. Интервью, реальная экономия времени, доступность из России без VPN, нагрузочное испытание и условия реального университетского запуска этой итерацией не подтверждаются.

## Что проверено фактически

- Сценарный тест сохранил отчёт [api-checks.json](api-checks.json): 74 локальные проверки, включая две конкурентные операции. В каждой гонке только один запрос завершился успешно, другой получил конфликт; история соответствует сохранённому состоянию.
- Браузер: заказ транскрипта, раскрытие подтверждения, отмена и запись в истории; переход из уведомления к уточнению; отдельное изменение статуса сотрудником и попытка отправить уже набранный текст. Сервер вернул 409, текст остался в поле. Это проверено по UI и значению textarea, не только по API.
- При ширине окна 360 px `scrollWidth = clientWidth = 345`; 15 px занимает полоса прокрутки среды. Горизонтального переполнения на проверенных новых экранах не было. Временная настройка экрана сброшена после проверки.

## Среда проверки

Локальная БД для текущей проверки изолирована от предыдущих демонстрационных обращений через `PORTAL_QA_STATE`. При запуске собранного Worker через закреплённый Wrangler наблюдался ответ 503 от локального прокси после отклонённого запроса; подменять ожидаемый отказ проверкой «любой 4xx/5xx» не стали. Полный прогон выполнен через штатный dev-режим Vinext; production-сборка проверена отдельно, HTTPS проверяется после публикации. Точная первопричина локального 503 не установлена; похожее сообщение описано в [официальном репозитории Cloudflare](https://github.com/cloudflare/workers-sdk/issues/14641).
